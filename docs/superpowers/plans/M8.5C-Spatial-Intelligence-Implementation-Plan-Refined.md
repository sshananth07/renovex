## Goal

Implement the complete M8.5C Spatial Intelligence V1 full-stack milestone as a sequence of testable vertical slices, including Go/Huma backend, Mongo persistence, object storage, async jobs, Web spatial workspace, iOS RoomPlan AR capture/preview (primary; Android AR capture/preview frozen — see §Task 5 — FROZEN), Qwen-based design generation, MapAnything refinement, real-time collaboration, versioning, and reviewed operational integration.

## Architecture

Go/Huma remains the authoritative application/domain boundary. iOS (via RoomPlan) performs AR-assisted field capture and lightweight AR concept interaction; Web provides the primary spatial planning/editor workspace. The frozen Android/ARCore provider previously held this field-capture role and may resume it as a future fallback (§Task 5 — FROZEN) behind the same `SpatialCaptureProvider` abstraction (design spec §8.7), but is not active for current M8.5C scope. AI/reconstruction providers remain advisory/provider-neutral, while all canonical geometry, validation, versioning, scene construction, collaboration commits, and operational handoffs are controlled by Renovex services.

`ScannerParameters` owns every tunable scanner threshold and scoring weight;
all reconstruction components receive the relevant nested configuration rather
than reading numeric file-level constants. Initial fixture-driven defaults are
explicit rather than distributed through UI code: 8° maximum
angle difference, 0.20 m maximum supporting-line offset, 1.25 m maximum extent
gap, 0.25 m minimum standalone observed extent, three observations across at
least 500 ms before stability, 3° maximum stable angular standard deviation,
0.08 m maximum stable offset standard deviation, and 0.25 smoothing alpha for
both direction and offset. Task 5L may tune these only with replay/device
evidence and must update fixtures and diagnostics with any change.

Defaults are scanner policy, not architectural truth. Tests must construct
non-default parameter values and prove the boundary immediately below, exactly
at, and immediately above the supplied value for angle, line offset, extent
gap, stabilization count/duration/variance, match scoring, intersection
plausibility, shell confidence, and coverage/guidance evidence thresholds.

Every production behavior below uses RED → GREEN TDD. Before changing a test,
name the production behavior that would make it fail, run the focused test and
confirm the expected failure, implement only that behavior, and re-run the
focused test. Do not preserve the old longest-diagonal or cluster-count
abstraction merely because its existing tests pass.

For the canonical undirected line representation, normalize the horizontal
normal and negate it when `x < 0`, or when `abs(x) <= 1e-6 && z < 0`. Derive
direction as `(-normal.z, normal.x)`, supporting-line offset as
`dot(normal, center)`, and observed start/end as the minimum/maximum
`dot(direction, polygonPoint)`. This exact sign rule prevents a 180° ARCore
normal flip from changing line identity.

```kotlin
data class WallMatch(
    val candidateId: String,
    val angleDifferenceRadians: Double,
    val supportingLineDistanceMeters: Double,

    val totalScore: Double,

        observation: WallObservation,
        candidates: Collection<WallCandidate>,
        config: WallTrackingConfig,
    ): WallMatch?
}

class WallCandidateTracker(
    private val config: WallTrackingConfig,
    private val idFactory: () -> String,
) {
    fun update(observations: List<WallObservation>, timestampMillis: Long): List<WallCandidate>
    fun snapshot(): List<WallCandidate>
}
```

Matching gates on angle, line offset, and extent compatibility before scoring
history. It must not use transitive single-link clustering, where one noisy
bridge can merge two otherwise incompatible walls.

Extent gap is zero for overlapping intervals and otherwise the distance
between their nearest endpoints after projecting the observation's reconstructed
endpoints onto the candidate direction. Reconstruct any line point from the
orthonormal representation as
`unitNormal * supportingLineOffset + unitDirection * projection`. Supporting
line distance is the maximum of the observation midpoint's distance to the
candidate line and the candidate midpoint's distance to the observation line;
this stays symmetric when the two accepted directions differ slightly.
After all three geometry gates pass, compatibility is scored from 0 to 1:

```text
angleScore   = 1 - angleDifference / maxAngleDifference
offsetScore  = 1 - lineDistance / maxSupportingLineOffset
extentScore  = 1 - extentGap / maxExtentGap
historyScore = min(candidate.observationCount / 5, 1)

totalScore =
    config.matchAngleWeight   * angleScore
  + config.matchOffsetWeight  * offsetScore
  + config.matchExtentWeight  * extentScore
  + config.matchHistoryWeight * historyScore
```

Choose the highest score, breaking an exact tie by stable candidate ID. Process
same-frame observations by `(timestampMillis, canonicalPlaneId)` so replay and
live execution are deterministic.

- Reproject the previous accumulated interval union onto the updated direction
  and union it with the new observation; merge only overlapping or touching
  evidence intervals, preserve real gaps, and never shrink established
  active-scan evidence because one update is shorter.
- Track angular and offset variance, observation count, first/last seen time,
  and stability. Promote only after the configured count, duration, and
  variance requirements pass.
- Permit a sub-minimum observation to update a matching candidate, but do not
  let it create a standalone stable candidate.

The exact update is:

```text
alignedIncomingNormal = sign-aligned to previous normal
smoothedNormal = normalize((1 - α) * previousNormal + α * alignedIncomingNormal)
smoothedDirection = perpendicular(smoothedNormal)
smoothedOffset = (1 - α) * previousOffset + α * incomingOffset

previous interval endpoints = previousNormal * previousOffset
                            + previousDirection * each interval projection
new interval union = normalizedUnion(
    every previous interval endpoint projected onto smoothedDirection,
    incoming interval endpoints projected onto smoothedDirection
)

outer start/end = min/max across the interval union
```

Stability is the configured weighted sum of count, duration, angular-variance,
and offset-variance scores, each clamped to `[0, 1]`. Promotion additionally
requires every configured hard threshold to pass; a high aggregate must not
hide one failing variance. Candidate state never demotes during one active
scan, although diagnostics continue to report new variance and last-seen time.


The builder forms an intersection graph, selects a simple ordered cycle from a
supported subset of stable candidates, uses each selected candidate at most
once, rejects self-intersection, scores observation support and candidate
stability, and treats camera-path crossings as a penalty rather than an
absolute rejection. It returns `Incomplete` rather than inventing a closing
wall.

Cycle scoring is deterministic and uses the four configured
`RoomShellConfig` weights for mean candidate stability, mean intersection
confidence, mean observed coverage of proposed shell edges, and camera-path
plausibility. Camera-path plausibility is the fraction of sampled camera
positions inside/on the candidate polygon using the configured boundary
epsilon; it is a score only, never a hard rejection. Exact score ties resolve
by the lexicographically sorted candidate-ID sequence.

The builder may close only a real cycle of selected stable candidate lines and
their supported intersections. It cannot create a synthetic candidate/edge to
close a gap, cannot rectangularize an angled or L-shaped cycle, and cannot add
intersection-derived extension length to `observedCoverageByCandidate`.
Coverage is computed only from the candidate's preserved observed interval
union intersected with the architectural shell edge.
