# M8.5B-A — AI Scope & Resource Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved M8.5B-A vertical slice end-to-end: contractor-authored Project Scope Brief → AI Space suggestions → governed Space review → AI Work Item suggestions (including supporting/missing/project-wide scope) → governed Work Item review → project-level AI Resource suggestions → governed Material/Trade/Equipment approval into real `WorkResourceRequirement` planning data, with a Python FastAPI/Gemini service behind Go + Huma and a complete Next.js UI.

**Architecture:** Browser → existing Next.js/OpenAPI client → authoritative Go + Huma API → authenticated internal HTTP → Python FastAPI AI service → provider-neutral `AIProvider` (`MockProvider` or `GeminiProvider`). Python never accesses MongoDB and never creates business objects. Go owns tenant authorization, context selection, input fingerprints, AI batch/suggestion persistence, stale/idempotency rules, and accepted-suggestion application through deterministic domain services. The existing commercial/financial path remains unchanged.

**Tech Stack:** Go + Chi + Huma v2 + MongoDB; Next.js + TypeScript + TanStack Query + React Hook Form + Zod + openapi-fetch/openapi-typescript + Vitest/RTL + Playwright; Python 3.12+ + FastAPI + Pydantic v2 + `google-genai` + pytest.

**Approved design:** `docs/superpowers/specs/2026-08-16-m8.5b-ai-scope-resource-preview-design.md`

## Global Constraints

1. **Read the approved design before changing code.** The design is authoritative for product semantics and AI boundaries.
2. **No Git commits.** Do not run `git add`, `git commit`, `git push`, create worktrees, or create Git metadata. Leave changes as working-tree modifications for user review. If the repository has Git, `git diff --check` may be used as a review command only.
3. **Do not silently redesign live contracts.** Task 0 is a read-only contract freeze. If the current repository contradicts a load-bearing assumption in this plan (tenant model, module ownership, WorkItem quantity invariants, public API patterns, auth/session model, OpenAPI generation), stop and report the contradiction before coding.
4. **Go remains authoritative.** Python must never receive MongoDB credentials or direct domain repositories/services and must never be browser-facing.
5. **No AI financial authority.** AI generation/acceptance must not create or alter `CostItem`, Estimate, Quotation, RFQ, Supplier Offer, Award, payment, committed/actual/paid amount, or any authoritative financial total.
6. **No AI-authored WorkItem quantity/unit.** Current WorkItem creation requires a positive exact-decimal quantity and non-empty unit. The contractor must supply these during Work Item acceptance.
7. **No duplicate hand-maintained frontend DTOs.** Public browser contracts come from Huma → `apps/web/openapi/openapi.json` → generated TypeScript types.
8. **Python internal schemas are separate from public Huma schemas.** Do not expose the Python internal service in the public OpenAPI.
9. **Exact quantities stay strings.** No JavaScript `Number` or Python float is used for Renovex authoritative quantities. AI confidence may be a bounded float because it is advisory only.
10. **Secrets never enter logs, MongoDB, OpenAPI, browser bundles, AI suggestion records, or error bodies.**
11. **Automated AI regressions use `MockProvider`.** Real Gemini is a separate synthetic smoke/evaluation gate.
12. **Use current official `google-genai`.** Use provider-supported structured output with Pydantic/JSON schema; do not regex-extract or “repair” arbitrary model prose.
13. **Keep files focused.** UI components render already-loaded state; query/mutation orchestration stays in feature hooks; Go handlers stay thin; Python routes delegate to orchestration/provider classes.
14. **Every task is TDD-first.** Write the focused failing test, run it and confirm the expected failure, implement the smallest production change, then run the focused suite and relevant regression gate.
15. **Do not weaken existing tests or security assertions to get green.**

# Execution Notes

- This plan is deliberately ordered so the provider boundary is proven first with `MockProvider`, the existing deterministic domain receives narrow provenance seams next, AI persistence/orchestration follows, and the Next.js UI is built only after the public Huma contract is real and regenerated.
- The first implementation action is Task 0’s **read-only repository freeze**, not scaffolding.
- The coding agent should stop only for a genuine contradiction involving security/tenant boundaries, money/quantity authority, module ownership, irreversible lifecycle semantics, or a live contract that makes the approved design impossible. Ordinary file naming/component decomposition differences should be resolved by extending the existing equivalent file rather than inventing parallel architecture.
